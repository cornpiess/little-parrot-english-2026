# 钢铁侠沉浸式冒险 V2：导师实施规格

> 案例名称：**《钢铁侠与黑云星的第一束光》**  
> 目标年龄：3 岁  
> 目标时长：约 5～6 分钟，以故事完整性为准  
> 学习目标：`star`、`light`  
> 实施原则：新建 `adventure-v2`，不得导入旧 `olaf-live/adventureRuntime`、`AdventureStageInteraction` 或旧 `minigames`。

## 0. 结论：真正要重构的是什么

旧结构的错误不是画面不够漂亮，而是把故事理解成“台词 beat + 继续按钮 + 小游戏卡片”。在这种结构里，角色只是报幕员，场景只是背景图，游戏是覆盖在故事上面的另一套界面。孩子必须理解产品 UI，才能让剧情继续。

V2 的基本单位必须是**可表演、可探索、可变化的世界场景**：

- 钢铁侠用台词、目光、飞行和对物体的操作主动推进故事。
- 孩子的触摸发生在星球、光束、云层、钢铁侠掌心等故事对象上，而不是“继续”“确定”“开始游戏”等 UI 上。
- 游戏不是弹出的卡片。进入飞行后，整个画面就是飞行世界；进入搜寻后，整个黑暗山谷就是搜寻空间。
- 没有孩子输入时，钢铁侠会提醒、示范、共同完成，故事不会卡住。
- 场景切换来自因果关系：钢铁侠启动推进器，所以实验室窗外变成云层；星球不断靠近，所以飞行自然变成降落。

一句话定义：**孩子不是在操作一份互动课件，而是在和钢铁侠共同经历一件正在发生的事。**

## 1. 面向 3 岁儿童的硬规则

这些是运行时规则，不是编剧建议。

1. **故事中禁止“继续”**。唯一可以存在的启动动作，是进入故事时一次大面积播放入口，用来满足浏览器音频解锁要求；进入故事后不再出现流程按钮。
2. **一次只要求一个动作**。钢铁侠每次只说一句短指令，如“跟着我飞”“找到那束光”“把光送过去”。
3. **角色先示范，孩子再参与**。动作提示顺序固定为：钢铁侠看向目标 → 身体预备 → 做出半次示范 → 看回孩子 → 留出行动窗口。
4. **不失败、不扣分、不重来**。孩子做错时，世界仍产生有趣但不完成目标的反馈；钢铁侠不说“错了”。
5. **任何互动最多等待 8 秒**：
   - 0～2.5 秒：目标通过自身运动、声音、明暗变化吸引注意；
   - 2.5～5 秒：钢铁侠短句提醒并指向目标；
   - 5～8 秒：钢铁侠示范一部分，孩子只需补最后一步；
   - 8 秒后：钢铁侠与孩子“共同完成”，剧情继续。
6. **触摸热区属于对象本身**，目标有效面积不小于 96×96 CSS 像素，但不能画黄色虚线圈、箭头按钮或通用高亮框。
7. **除目标单词外不显示文字**。`STAR`、`LIGHT` 只在它们与真实对象建立联系时短暂出现。成人调试信息必须在独立开发面板，不进入儿童舞台。
8. **孩子可以乱点**。任何位置都应有轻微世界反馈，如星尘、光波、金属回声，但不得误推进剧情或导致异常。
9. **摄像头、麦克风都不是通关条件**。拒绝权限后，触摸仍能完整体验故事。
10. **钢铁侠负责节奏**。他说完、做完、确认孩子反应后，自然转身、起飞、落地或操作物体，由这些动作触发下一段。

## 2. 故事 DNA

为了未来能做 1000 个故事，每个故事必须先填写七个不能互相替代的字段。只换皮肤、单词和背景不算新故事。

| 维度 | 本案例 |
|---|---|
| 核心幻想 | 孩子拥有一双由钢铁侠授权的光能手套，能和他并肩飞行、寻找和传递光 |
| 情感问题 | 真正的英雄，是打败看起来可疑的人，还是先弄清他为什么这样做？ |
| 孩子身份 | 光能领航员，不是观众、副驾驶缩略图或答题者 |
| 世界规则 | 黑云星的光会沿水晶脉络流动；风暴会吹散光，合作能让光稳定下来 |
| 空间旅程 | 实验室 → 高空云层 → 太空接近 → 黑云星山谷 → 灯塔内部 → 星球晨光 |
| 标志性场面 | 远方星球从一个小点长到占满画面；孩子和钢铁侠共同点亮横扫天际的灯塔 |
| 解决方式 | 不是击毁敌人，而是发现维护机器人正在保护小星星，再共同制造足够的光 |

## 3. 角色关系

### 钢铁侠

钢铁侠不是解说员，而是同时承担四个职责：

- **故事发动机**：接到信号、判断路线、起飞、调查、安装灯塔镜片。
- **孩子的注意力导演**：用目光、头部朝向、掌心方向和站位告诉孩子“现在看哪里”。
- **合作伙伴**：关键任务永远由他完成一半、孩子完成一半。
- **情绪保护者**：危险以“紧张但可控”呈现；他会挡在孩子与风暴之间。

故事蓝图只写表演意图，如 `invite-child`、`scan-world`、`shield-child`、`celebrate-together`。角色模块再把意图编排成连续动作。蓝图不得直接写动作名。

当前钢铁侠可以复用的动作素材：`listening`、`thinking`、`speaking`、`greeting`、`nod`、`fly`、`surprised`、`peek`、`repulsor-blast`、`cheer`。**禁止使用 `happy`**。每个动作都要有预备、主动作、反应、收势，不能直接在循环动作之间硬切。

### 孩子

采用第一人称角色，不再把摄像头长期放成右下角小头像：

- 屏幕底部偶尔出现两只半透明光能手套，代表孩子的身体。
- 触摸位置决定手套伸向哪里；按住时掌心能量逐渐稳定。
- 摄像头只在“头盔连接”或钢铁侠呼叫孩子时短暂出现在装甲反射面中，可关闭。
- 钢铁侠看向屏幕中心并适度移开视线，让孩子感到被看见，但不会被死盯。

### 莫莫维修机器人

外形最初只是远处黑色剪影，像“拿走光的人”；近看是一个笨拙、圆润、只有一盏小灯的维护机器人。它拿走灯塔晶体，是为了给坠落的小星星保暖。这个转折让故事从“追捕”变为“理解与合作”。

## 4. 完整剧本与场景调度

### 序幕：求救信号（约 30 秒）

**远景**：夜色中的城市天际线，云层缓慢移动；窗外没有杂乱飞行物。  
**中景**：斯塔克实验室中央是一张弧形工作台，台面浮起黑云星全息模型。模型的灯塔一明一灭。  
**近景**：左下是装甲工作台边缘，右下是孩子尚未点亮的光能手套轮廓。

钢铁侠背对孩子修理一个掌心模块。远处传来三声微弱的“滴、滴、滴”。他停止手部动作，先侧头，再转身看向全息模型，进入 `listening` 意图。

短台词：

- “嘘……有个小家伙在呼叫我们。”
- 全息画面出现一颗瑟瑟发抖的小星星。
- “它的灯塔灭了。没有光，它找不到家。”
- 钢铁侠看向孩子：“领航员，我们去把光找回来。”

不出现选择按钮。钢铁侠伸出掌心，掌心光照向孩子手套，自动进入下一场。

### 第一幕：光能手套连接（约 25 秒）

实验室灯光压暗，钢铁侠掌心成为唯一强光源。他把手伸到画面前景，掌心是一个真实可触摸的故事对象。

孩子触摸掌心后，能量沿 SVG 光路流到屏幕底部两只手套。若孩子没有触摸，钢铁侠说“碰一下我的手”，把手再向前送；最后与孩子共同完成连接。

台词：

- “这不是按钮，是我们的能量握手。”
- 连接成功后，他点头：“连接完成。跟紧我。”

钢铁侠转身助跑，两脚推进器点火。推进光充满画面，成为下一场的转场遮罩。

### 第二幕：飞向黑云星——全屏飞行（约 50 秒）

这是第一段完整游戏，不能出现游戏框、操纵按钮或进度条。

**远景**：目标星球起初只有画面中央 6% 大小，灯塔发出微弱闪光；星野缓慢旋转。  
**中景**：三条柔和云带和少量发光尘埃形成飞行路线。  
**近景**：孩子的头盔边缘极淡可见；钢铁侠在左前方飞行，不挡住目标。

玩法：孩子在屏幕任意位置拖动，控制自己的光迹向该方向弯曲。不是控制一个飞船图标，而是移动第一人称飞行方向。钢铁侠根据孩子的方向调整自己的编队位置。

世界反馈：

- 接近正确航线时，云层从两侧滑过，目标星球持续变大。
- 偏离航线时不会撞击；钢铁侠飞到孩子前方，用身体和光迹重新画出路线。
- 经过三个星尘带时，星尘从前景掠过并发出空间声，不显示加分。

台词只在画面需要时出现：

- “看前面，那颗小小的 **star**。”
- 目标旁短暂出现 `STAR`，随后融入星光。
- “跟着我的光迹，我们飞过去。”

星球从 6% 放大至约 70%，云层开始包围镜头，飞行连续进入风暴。

### 第三幕：穿过磁光风暴（约 35 秒）

飞行控制不退出，只改变世界规则。紫蓝色磁光云从左右卷入，钢铁侠被吹离半个身位。他先稳住自己，再飞到孩子与风暴之间。

玩法：孩子用手指在屏幕上划出一条连续弧线，光能手套沿路径扫开云层。清开的区域直接露出后方星球，不是画出抽象进度。

钢铁侠的合作动作：孩子扫左侧，他用掌心推开右侧；孩子停下，他先保持通道，再用目光邀请孩子继续。

台词：

- “风暴来了。别怕，我在前面。”
- “你清左边，我清右边。”
- 通道打开：“就是这样——星球就在前面！”

最后一层云贴近镜头并完全遮住画面。云散开时已经是星球地表，完成无菜单转场。

### 第四幕：黑玻璃山谷（约 35 秒）

**远景**：一座熄灭的灯塔立在山谷尽头，塔顶轮廓清晰但没有光；天空仍有缓慢旋转的风暴。  
**中景**：黑色玻璃岩石、断开的浅蓝水晶脉络、通往灯塔的弯曲路径。  
**近景**：少量发光草叶和刚落地扬起的尘埃，不遮挡钢铁侠手臂。

钢铁侠从飞行姿态自然转为落地缓冲，不能瞬间换成站立。他先扫视灯塔，再发现地面有一串微弱脚印。他蹲低或侧身探查，进入 `peek` / `scan-world` 意图。

台词：

- “灯塔真的灭了。”
- “地上有小小的光脚印。它们通向那边。”

钢铁侠沿脚印走入画面深处。镜头随他向前移动，自动进入搜索场景。

### 第五幕：寻找小星星——全屏光束搜索（约 45 秒）

山谷变暗，孩子的一只光能手套出现在屏幕下方。手指移动到哪里，真实手电光束就照向哪里。光束必须改变岩石、草叶和尘埃的亮度，而不是在页面上叠一个透明圆圈。

玩法：

- 左侧岩石后有会缩起来的发光植物；照到时会发出清脆声，增加探索感，但不算错误。
- 右侧水晶会把光折射到远处，产生短暂彩色光带。
- 中央偏深处藏着小星星。照到附近时，先听到轻微呼吸声，再看见暖黄色反光。
- 钢铁侠在另一区域同步搜索，会转头关注孩子照到的对象。

找到后，他立即靠近但停在一段安全距离，降低身体高度，先观察小星星是否害怕。

台词：

- “慢慢照，我们听听哪里有声音。”
- 找到时轻声说：“找到了。一颗小 **star**。”
- `STAR` 从小星星身体里随呼吸亮起一次，不做单词卡片。
- “可以和我一起叫它吗？Star。”

语音识别和触摸小星星都可以回应。没有回应时，钢铁侠自己先轻声叫一次，再邀请孩子和他一起叫，不阻塞剧情。

### 第六幕：误会揭开（约 35 秒）

一只黑色机械手从岩石后伸出，钢铁侠本能抬起掌心但不发射。他把身体置于孩子与机械手之间。维修机器人莫莫慢慢走出，怀里抱着拆下来的灯塔晶体；晶体正给小星星保暖。

环境必须把因果画清楚：小星星靠近晶体时变暖、远离时发抖；远处灯塔因为缺少同一晶体而熄灭。

钢铁侠先扫描，再缓慢放下手。他不是通过旁白解释，而是看小星星、看晶体、再看灯塔，做出理解反应。

台词：

- “等等。它没有偷走光。”
- “莫莫在用灯塔晶体保护小星星。”
- 他看向孩子：“我们不抢回来。我们做更多的光。”

这一步是故事灵魂：孩子看到英雄会改变判断，而不是遇到黑色角色就攻击。

### 第七幕：唤醒水晶脉络——全屏能量传递（约 50 秒）

镜头沿地面水晶脉络滑向灯塔。整个山谷成为能量路线图，但所有路线都是场景内真实存在的水晶裂纹。

玩法分三次自然完成：

1. 钢铁侠站在第一块水晶旁，掌心接触水晶。他的能量只点亮路线的一半。
2. 孩子按住任意位置，光能手套与当前水晶建立光束；两股能量汇合后，第一段地脉向远处点亮。
3. 镜头跟随光沿山谷前进，下一块水晶进入近景。孩子拖动光束，把能量引向它；钢铁侠飞到第三块水晶处接力。

没有进度条。**被逐段照亮的山谷本身就是进度。** 每完成一段，远处灯塔的轮廓就清晰一点。

台词：

- 第一段：“我有能量，你有方向。一起。”
- 光汇合：“看，**light** 在跑！”
- `LIGHT` 沿真实光束出现后迅速散成粒子。
- 最后一段：“把 light 送到灯塔！”

### 第八幕：守住第一束光（约 35 秒）

钢铁侠飞到灯塔顶部安装新镜片；莫莫在塔底稳定晶体；小星星在孩子旁边提供暖光。风暴再次压近，刚形成的光束开始摇晃。

玩法：孩子按住屏幕中央的真实光束，光能手套生成一个由场景光线构成的保护罩。保护罩不是圆形 UI，而会真实改变云层方向、塔身高光和尘埃运动。孩子松手时光束轻微摇晃，但不会失败。

钢铁侠在塔顶完成安装，回头看向孩子并点头。若孩子没有按住，他会先用一只掌心撑住保护罩，另一只手继续安装；孩子只需触碰一下即可加入。

台词：

- “风暴想把光吹走。帮我守住它。”
- “再一小会儿……好了！”
- 灯塔点亮时：“Let there be light——有光啦！”

### 尾声：星光回家（约 30 秒）

灯塔光束横扫天空。每扫过一处，黑云背后就出现一颗星；远景由深蓝变成清晨紫色。小星星沿光束升起，加入远处的星群。莫莫的身体也被光照成温暖颜色。

钢铁侠从灯塔飞回近景，先看小星星安全归队，再看孩子。他不使用 `happy`。采用 `nod → greeting/high-five → cheer` 的短序列：先确认任务完成，再把掌心伸向孩子。

孩子触摸他的掌心后，两束掌心光在画面中央形成一颗星，而不是出现奖牌、分数或结算卡。

台词：

- “Star 找到家了，light 照亮了路。”
- “你先看见了真相，也守住了光。那才是英雄。”
- “击掌，领航员。”

光星扩散为下一页的返回转场。故事至此完整结束。

## 5. 全屏游戏的统一定义

V2 不存在 `Minigame` 模块。游戏是一段改变世界控制规则的场景状态，称为 `PlayableScene`。

| PlayableScene | 整个世界如何变化 | 孩子输入 | 可见进度 | 钢铁侠如何参与 |
|---|---|---|---|---|
| `flight-approach` | 摄像机持续前进，星球由远变近，云层产生视差 | 全屏拖动控制飞行方向 | 星球大小、云层速度、距离音效 | 与孩子编队、用飞行轨迹领航 |
| `storm-clearing` | 磁光云真实遮挡目标星球 | 全屏划动清开云层 | 可见天空面积和通道宽度 | 清理另一侧、保护孩子 |
| `light-search` | 场景处于真实低照度，光束改变物体材质 | 移动指针控制光束 | 被发现的环境和声音线索 | 在另一侧搜索、对发现做反应 |
| `energy-relay` | 水晶地脉逐段改变发光状态 | 按住充能、拖动引导光束 | 山谷自身被点亮的距离 | 在不同水晶间接力 |
| `shield-the-light` | 风暴粒子和灯塔光束受保护罩影响 | 按住稳定、移动调整罩面 | 光束稳定度、云层偏转 | 一手支撑、一手完成安装 |

所有 PlayableScene 必须满足：

- 占用 100% 故事舞台，角色仍在世界里；
- 不显示“玩法说明”，由角色示范和世界反馈教学；
- 不显示得分、生命、倒计时、星级或通用进度条；
- 进入和退出都由故事动作触发；
- 支持无输入自动协作完成；
- 在触摸、鼠标、摄像头手势不可用时仍有降级路径。

## 6. V2 技术架构

### 6.1 外部 seam：只有一个深 Module

页面不应该理解剧情节点、小游戏类型、动作名字和转场条件。页面只挂载一次体验：

```ts
export interface AdventureSession {
  begin(): void;                     // 一次音频解锁后开始
  send(signal: ChildSignal): void;   // 触摸、语音或可选视觉信号
  frame(atMs: number): ExperienceFrame;
  dispose(): void;
}

export function createAdventureSession(
  episode: EpisodeBlueprint,
  adapters: AdventureAdapters,
): AdventureSession;
```

这是运行时唯一对页面公开的 Interface。测试也只通过这个 Interface 验证。复杂的导演、角色、世界、协助策略和转场都藏在实现中。

### 6.2 领域结构

```text
Episode
├─ NarrativeDNA        故事为何独特
├─ Cast                角色身份与能力
├─ LearningArc         1～2 个目标词如何嵌入因果
└─ Acts
   └─ Scenes           持续存在的空间与世界状态
      └─ Moments       场景内的戏剧变化，不等于页面或按钮
```

Scene 的结束条件只能来自三类事实：

- `performance-complete`：钢铁侠完成台词和收势，世界动作也已稳定；
- `world-goal`：星球已接近、云已清开、光已到达灯塔；
- `co-action-resolved`：孩子完成、钢铁侠协助完成或超时共同完成。

禁止出现 `continue`、`nextBeat`、`skipBeat` 作为儿童故事事件。开发者可以有仅在 debug 模式出现的跳转工具，但不得进入生产 DOM。

### 6.3 内部 Modules

```text
src/features/adventure-v2/
├─ createAdventureSession.ts       # 唯一外部 Interface
├─ domain/
│  ├─ episode.ts                   # EpisodeBlueprint 与校验
│  ├─ signals.ts                   # ChildSignal
│  └─ frame.ts                     # ExperienceFrame
├─ runtime/
│  ├─ narrativeDirector.ts         # 因果推进、场景连续性
│  ├─ engagementDirector.ts        # 2.5/5/8 秒帮助阶梯
│  ├─ transitionDirector.ts        # 匹配剪辑、飞行、遮罩转场
│  ├─ dialogueDirector.ts          # TTS、停顿、打断、口型时钟
│  └─ learningDirector.ts          # 单词出现、复现与回忆
├─ world/
│  ├─ WorldStage.tsx               # 单一全屏 SVG/HTML 舞台
│  ├─ sceneGraph.ts                # 摄像机、灯光、对象状态
│  ├─ objectCatalog.ts             # 对象 anchors 与状态机
│  └─ materialCatalog.ts           # 光、云、水晶等视觉材料
├─ play/
│  ├─ flightApproach.ts
│  ├─ stormClearing.ts
│  ├─ lightSearch.ts
│  ├─ energyRelay.ts
│  └─ shieldTheLight.ts
├─ characters/
│  └─ ironManAdventureProfile.ts   # 意图 → 连续动作编排
└─ episodes/
   └─ iron-man-first-light/
      ├─ episode.ts
      ├─ dialogue.ts
      ├─ scenes.ts
      └─ assets/
```

这些 Play Module 先作为 V2 的内部 seam。只有第二个故事真正需要替换实现时，才抽象公共 adapter；不要为了“未来 1000 个故事”预先制造几十个空 Interface。

### 6.4 EpisodeBlueprint 示例

内容作者描述戏剧事实，不写 CSS、坐标动画或角色动作名：

```ts
export const IRON_MAN_FIRST_LIGHT: EpisodeBlueprint = episode({
  id: 'iron-man-first-light',
  teaching: { words: ['star', 'light'], maxVisibleWords: 1 },
  cast: {
    lead: 'ironman',
    childRole: 'arc-light-navigator',
    companions: ['momo', 'little-star'],
  },
  acts: [
    act('departure', [
      scene('signal-lab', {
        world: 'stark-night-lab',
        purpose: 'receive-call-and-recruit',
        heroIntent: 'listen-then-invite',
        exit: performanceComplete(),
      }),
      scene('approach-planet', {
        world: 'black-cloud-orbit',
        purpose: 'travel-together',
        play: flightApproach({ destination: 'black-cloud-star' }),
        exit: worldGoal('destination.reached'),
      }),
    ]),
  ],
});
```

具体相机轨迹、星球放大、帮助策略和钢铁侠飞行姿态由运行时根据 world、purpose、play 和角色 Profile 生成。

### 6.5 ExperienceFrame

渲染层每帧只消费一个统一结果：

```ts
interface ExperienceFrame {
  camera: CameraFrame;
  lighting: LightingFrame;
  layers: { far: WorldNode[]; middle: WorldNode[]; near: WorldNode[] };
  actors: ActorFrame[];
  props: PropFrame[];
  childEmbodiment: ChildBodyFrame;
  soundscape: SoundscapeFrame;
  learningCue?: { word: 'star' | 'light'; anchorId: string; strength: number };
}
```

世界对象必须有语义 anchor，例如 `ironman.rightPalm`、`lighthouse.lens`、`crystal.input`、`littleStar.center`。抓取、光束、视线和触摸都连接 anchor，禁止用页面百分比猜测手在哪里。

## 7. 场景美术规范

### 7.1 三层不是三堆装饰

- **远景回答“我们在哪里、要去哪”**：星球、灯塔、山脉、天空状态。
- **中景承担因果和玩法**：云层、路径、水晶脉络、机器人、灯塔机械结构。
- **近景承担身体与速度**：孩子手套、掠过镜头的云和尘埃、钢铁侠伸向镜头的手。

每个元素都必须至少承担一项职责：空间尺度、剧情线索、交互对象、情绪光线或转场遮罩。纯装饰元素数量要受限，避免眼花缭乱。

### 7.2 禁止项

- 生产场景不得用 emoji 充当苹果、星球、机器人、按钮或反馈。
- 不使用黄色虚线椭圆、旋转目标圈、漂浮 UI 卡片。
- 不在每个场景都使用同一种粒子、同一种光晕或同一种庆祝彩带。
- 不把角色手部、脸部和故事焦点挡在前景装饰后面。
- 不通过突然 `display:none` 切走对象；对象离场必须有缩小、遮挡、飞出、熄灭或被角色拿走的因果。

### 7.3 轻量化实现

- 背景使用少量 SVG path、渐变和 CSS transform，不用视频背景。
- 远景以低频动画为主；同一时间最多一个中景系统和一个近景系统进行高能运动。
- 用统一 viewBox 和相机矩阵制造 2.5D 纵深：远景视差 0.25，中景 0.6，近景 1.15。
- 物体采用状态变体，如 `dark → warming → lit`、`far → approaching → arrived`，而不是每幕重新生成一份 DOM。
- 低性能设备降级粒子数量，不改变剧情和关键因果。

## 8. 台词与声音规则

- 每个口语块只表达一个意思，中文通常不超过 16 个字；长信息拆成动作之间的两句。
- 场景进入后 300ms 内启动首个声音 cue，不允许沉默十几秒。
- TTS、口型、身体语气共享同一时钟；音素驱动嘴型，句子重音驱动掌心和头部强调。
- 钢铁侠不是幼儿音，声音应稳定、温暖、自信，语速约正常成人的 0.82～0.9；危险时更短、更稳，不靠大喊。
- 环境声在台词时自动降低约 6～9dB；关键世界反馈要有空间方向。
- 单词遵循“先看见含义，再听词，再尝试说，再用行动证明”的顺序，不能突然停下来上单词卡。

## 9. 为 1000 个故事建立的生产方法

### 9.1 教研先写 Story Contract

每个故事先提交一页 Contract：

1. 七项 Narrative DNA；
2. 孩子在故事里究竟能做什么现实动作；
3. 三个世界状态变化，例如“黑暗山谷 → 光沿地脉传播 → 灯塔照亮天空”；
4. 角色和至少三个世界对象的真实关系；
5. 1～2 个学习目标如何改变剧情结果；
6. 无输入时角色如何共同完成；
7. 这个故事唯一的标志性场面。

如果删除角色名字、背景颜色和单词后，Contract 与已有故事仍相同，就不进入制作。

### 9.2 可复用的是语法，不是套路

可复用库分为四类：

- 世界材料：水、云、太空、森林、机械结构、光线；
- 空间动词：接近、穿越、寻找、护送、搭建、唤醒、守护；
- 角色表演意图：邀请、发现、保护、犹豫、理解、合作、庆祝；
- 输入语法：全屏引导、搜索光束、按住稳定、节奏同步、拖动连接。

故事作者组合这些语法，但 Narrative DNA、因果链、情感转折和标志性场面必须单独创作。引擎负责可靠执行，不负责把所有故事写成同一套模板。

### 9.3 编译校验

建立 `validateEpisode(blueprint)`，在 CI 中拒绝：

- 目标词超过 2 个；
- 儿童舞台出现非目标文字；
- 生产节点包含 `continue`、`nextBeat`、`skip`；
- 互动没有 2.5/5/8 秒协助策略；
- 场景引用不存在的对象、状态或 anchor；
- 学习词没有对应真实对象或世界结果；
- 使用角色 Profile 禁止的表演意图或动作，本案例包括 `happy`；
- PlayableScene 只占局部矩形或渲染成弹窗；
- 故事没有无输入完成路径。

## 10. Luna Max 实施顺序

### 阶段 1：只做连续世界，不做游戏

1. 新建 `src/features/adventure-v2`，不修改 V1 类型。
2. 实现 `createAdventureSession` 的最小 Interface。
3. 实现实验室、太空接近、黑云星地表、灯塔四个连续世界。
4. 完成三条转场：推进光遮罩、星球接近、云层落地。
5. 证明没有继续按钮也能从序幕自动走到尾声。

### 阶段 2：角色成为导演

1. 建立 `ironManAdventureProfile`，把戏剧意图编排为已有 Rig 动作序列。
2. 增加世界对象 anchor；目光、掌心光束、抓取全部基于 anchor。
3. 为每段表演加入 anticipation、action、reaction、settle。
4. 明确禁用 `happy`，并写测试保证 Episode 不会产生它。

### 阶段 3：把四个玩法做成世界状态

按 `flight-approach → light-search → energy-relay → shield-the-light` 的顺序实现。每完成一个玩法，都先验证：

- 是否占满舞台；
- 角色是否仍在世界中合作；
- 世界本身是否显示进度；
- 8 秒无输入是否能自然共同完成；
- 退出是否直接进入下一段剧情。

### 阶段 4：声音与学习闭环

1. 台词按本规格拆成短 cue。
2. 首句延迟控制在 300ms 内。
3. `star` 和 `light` 绑定到世界 anchor，不做卡片。
4. ASR 成功、ASR 失败、麦克风拒绝三条路径都能推进。
5. 角色对孩子的真实输入做具体反应，不只说“太棒了”。

### 阶段 5：导演级打磨

1. 完成全故事光线弧线：冷蓝实验室 → 紫蓝风暴 → 黑暗山谷 → 暖黄灯塔 → 紫金晨光。
2. 控制每场视觉焦点不超过两个。
3. 检查所有手部动作未被近景遮挡。
4. 检查对象都有合理入场、持有和离场。
5. 在 1280×720、1024×768、390×844 三个视口验收。

## 11. 验收标准

自动测试和人工验收必须同时满足：

1. 项目不存在 `/olaf-adventures-1` 和 `/hero-adventures` 路由。
2. V2 代码不导入 V1 冒险 Runtime、旧小游戏或旧舞台交互。
3. 故事运行中不存在“继续”“下一幕”“跳过互动”儿童控件。
4. 四段 PlayableScene 都占满故事舞台，没有弹窗式小游戏。
5. 飞行中目标星球从约 6% 连续增长到约 70%，随后因果进入地表。
6. 无任何儿童输入时，故事仍在合理帮助后完整结束，不会长时间沉默或卡死。
7. 随机连续触摸 100 次不会崩溃、跳幕或产生错误完成。
8. 摄像头与麦克风拒绝后仍可完整体验。
9. 每次孩子完成动作，钢铁侠都有朝向孩子的反应和对应世界结果。
10. 生产视觉不用 emoji，不出现通用黄色目标圈。
11. 视觉文字只有 `STAR` 与 `LIGHT`。
12. 钢铁侠全故事不调用 `happy`。
13. 页面音频解锁后，每次场景首句延迟小于 300ms。
14. 30fps 低性能模式下不改变关键故事动作；常规桌面目标 60fps。
15. 3 名从未看过说明的成人代替幼儿测试时，都能只凭钢铁侠表演完成全部互动；随后再进行真实幼儿观察测试。

## 12. 实施时最重要的判断

不要从“如何做一个通用故事编辑器”开始。先把这个钢铁侠案例做到真的像一次冒险，再从第二个高质量故事中寻找真实重复点。外部 Interface 从第一天保持很小，内部实现可以随着案例变深。

如果 Luna Max 遇到取舍，优先级固定为：

1. 孩子能否明白此刻发生了什么；
2. 钢铁侠是否像伙伴一样主动表演和推进；
3. 世界是否对孩子动作产生清晰因果；
4. 故事是否完整、有转折、有情感结果；
5. 最后才是代码复用率和视觉装饰数量。

这个案例的惊艳感不会来自更多粒子或更多按钮，而来自四个连续事实：**钢铁侠真的带孩子离开实验室、星球真的越来越近、孩子真的在黑暗世界找到一个生命、两个人真的共同点亮了整个天空。**
