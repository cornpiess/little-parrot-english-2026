# 雪宝 Live Lab

打开 `/olaf-live-lab` 可进入独立实验页面。即使没有模型凭证，页面也能用“无限连续表演空间”观察本地实时表演模型。

## 新架构

### 当前冒险实现（2026-08）

冒险舞台已经按四个可替换注册表落地：`Character Kit`（角色能力与原生装备）、`Story Pack`（剧本节拍与学习目标）、`World Kit`（世界视觉语言）和 `Mechanic Kit`（路线、节拍、修理、方向等儿童互动语法），并由 `AdventureActor` 把语义动作映射到角色 Rig。因此同一个故事可以替换雪宝、钢铁侠或巴斯光年，而不会复制舞台流程；钢铁侠和巴斯光年不会被错误地套上雪宝潜水服。

当前剧场包含海洋、恐龙、星光灯塔、钢铁侠彩虹能源城和巴斯光年上下颠倒日五个完整故事。新的能源核心、磁铁和重力盒使用独立 SVG 视觉键，未覆盖的概念才回退到安全 Emoji。Azure 语音适配器支持按当前/后两拍预加载并共享合成缓存，切幕时复用已准备好的音频和 viseme 时间轴。

页面和实时会话通过五层演员系统控制角色：

```text
稳定人格：温暖、好奇、笨拙但勇敢
                  ↓
戏剧目标：庆祝 / 安慰 / 邀请 / 发现 / 鼓励 / 逗乐 / 倾听
                  ↓
演员状态：情绪、注视、重心、空间关系
                  ↓
动作编排：察觉 → 判断 → 准备 → 行动 → 反馈 → 收势
                  ↓
RealtimePerformanceModel → CharacterRigFrame → SVG Rig
```

模型的外部接口只有三个操作：

- `ingest(...inputs)`：输入语音特征、注意力、角色 presence 或连续表演意图。
- `advance(timestampMs)`：推进统一表演时钟并返回完整 Rig 帧。
- `reset(timestampMs)`：清空会话状态并返回中性 Rig。

`CharacterRigFrame` 不包含动作名称或动画片段。它持续输出脸部、双眼、头部、躯干、左右手臂和动力学参数。表情、视线、呼吸、说话脉冲和身体动作因此可以在同一帧叠加。

六段表演现在由独立的 `PerformanceScore` 采样，而不是只停留在导演层的文字标签。每一帧都带有蓄力、主动作、反馈惯性、停顿和收势五条连续曲线；模型、SVG 和声音适配器消费同一份表演谱，因此“先缩一下再跳”“手停住而头继续跟随”“说完以后看孩子反应”都能成为真正的时间结构。

SVG 身体不再作为一张整体贴图移动。下身、中段和头部是三个具有不同响应速度的表演段：下身先承担重心与落地，中段传递力量，头和鼻子保留方向与跟随惯性；树枝头发、双臂和双脚还有次级摆动。这些仍是同一个连续 Rig，而不是把新的动画片段叠回去。

当前本地策略采用 3 岁幼儿表演配置：手臂使用完整的向上/向下范围，左右不对称会同步影响手臂、歪头和身体侧倾，节拍会产生明显弹跳与挤压。新的意图可以随时覆盖当前目标，Rig 会连续过渡而不是切换动画片段。

## 无限连续表演空间

页面不再提供有限的命名动作按钮，而是开放愉快度、情绪唤醒、动作能量、身体开放、上下趋势、前后倾向、左右差异和节拍驱动 8 个连续维度。它们还会与实时声音特征和注视目标共同组合，因此角色不是从动作列表里选片段。

“无限即兴”生成的不是一串固定动作，而是一系列有戏剧目标的“演员状态”。演示节奏下每个状态持续约 7.6–9.2 秒，比原先的 9.2–12 秒更紧凑；七类目标每轮洗牌，但每次的情绪混合、注视、姿态、空间位置、强度和节奏都会重新生成。状态内部固定经过察觉、判断、准备、行动、反馈和收势六个表演节拍，旧状态的情绪余韵会延续到下一次察觉。目标每 140ms 更新，Rig 在 60 FPS 时钟上连续追随。三秒节拍现在只是一次“可以说话”的检查机会：上一句必须完整播放，随后保留约 0.9–1.8 秒的自然反应停顿，再从当前戏剧目标的候选池中选择下一句；新台词不会为了追赶时钟而截断旧台词。

这里的“无限”指连续参数组合形成开放式状态空间，而不是无限堆积预制动画。动作语法仍负责约束关节和空间逻辑，例如手臂张开时位于身体后方、双手向胸前汇合时切换到身体前景层。这样既能持续生成新表演，也能避免手臂穿过身体或在背后拍手。

## 儿童单口剧场

“剧场随机”与“无限即兴”是两套并列模式，原来的无限连续表演完整保留。剧场模式不会生成一段长稿让角色朗读，而是锁定一个完整的儿童单口场景，再依次表演抓住注意、铺垫、升级、转折、小包袱、回扣和暖心收束七个短拍。每拍只有一句幼儿能理解的短台词，并绑定一个连续表演 motif；推进由真实表演完成事件驱动：一句完整说完，且当前动作至少走到反应和收势阶段，才会进入下一拍。包袱和结尾会得到更长的停顿。30 秒只作为编剧控制篇幅的参考，不再强制换拍或切场。

首批剧目包括雪宝的暖暖安慰、小队长冰雪冒险、今天我要夸夸你、雪宝的小小心声、我的迪士尼朋友们、雪人的搞笑一天、雪宝的英语魔法和睡前的一朵小雪花。剧目顺序按种子随机排列，同一轮八组不重复；无论语速、网络合成耗时或动作时长如何变化，一组都必须完成七拍和最终收势后才进入下一组。界面显示“第几拍”，不再用倒计时催促演员。

离线无限即兴会在部分演员状态里插入短暂台词窗口，并通过角色语音模块合成音频。语音返回的 viseme 时间戳会被映射成闭唇、张口、咧嘴和圆唇等连续嘴型，再与面部、眼神和身体动作共享表演时钟。进入真实模型会话后，无限预览自动停止，避免与模型语音争抢嘴型和音频输出。

### 表达语法与空间运动

仅靠连续情绪轴无法表达“拍手”或“摇头”的语义，因此完整 Rig 还包含一层可组合的身体语法。`ExpressiveIntent` 提供喜悦、痛苦、点头、摇头、双手会合、抽泣和节奏通道：哭泣会同步驱动眉眼、噘嘴、眼泪和躯干抽动；拍手会让双臂周期性向身体中线会合；认同和拒绝分别驱动纵向与横向头部周期。

页面提供 30 种导演状态，分为情绪反应、互动沟通、思考观察、空间动作和声音表演五组。每个状态只是“戏剧目标 + 表演变体”，不是录制好的动画片段；它仍会经过六段表演节拍，并在强度、方向、节奏、注视与空间位置上产生连续变化。目录中包括开心拍手、委屈哭泣、忍住眼泪、点头认同、摇头拒绝、好奇歪头、招手邀请、左右寻找、快步跑来、踮脚偷看、凑近说秘密和放松呼吸等状态。

`RootMotionRig` 让角色离开原地：水平位置、舞台景深、身体朝向、步态相位、腾空高度和地面接触都属于完整 Rig 帧。SVG 渲染器据此改变屏幕位置、透视缩放、左右脚交替、跳跃高度和阴影，形成走近、远离、踱步和跳跃的 2.5D 空间感。

Gemini Live 默认调用紧凑的 `perform_turn` 工具，只需表达“希望孩子感到什么”以及可选的物体动作；本地具身导演把它展开成完整表演。模型不接触关节坐标和 SVG 层级。

## 表演模型适配器

`PerformancePolicyAdapter` 是替换模型的 seam。当前 `LocalCausalPerformancePolicy` 是无模型权重也能运行的确定性因果适配器；它不是最终的学习模型，但已经使用与未来模型相同的连续 Rig 契约。

摄像头感知中的明显微笑和挥手走低延迟“演员反射”通道，不等待 LLM：雪宝会先回看、回笑或回应招手，再把事件交给对话模型理解。这样语言模型负责意义，实时表演模型负责一百毫秒量级的社交反应。

后续可增加：

- `Audio2FacePolicyAdapter`：接收带时间戳的 blendshape 流并填充 `FaceRig`。
- `WebGpuPerformancePolicyAdapter`：在浏览器中运行量化 ONNX/Transformer 表演模型。
- `RemotePerformancePolicyAdapter`：从 GPU 推理服务接收 25～30 FPS Rig 帧。

这些适配器只替换模型实现，不需要修改页面、会话控制或 SVG Rig。

## 模型与具身教学的职责

实时模型只调用一个紧凑的 `perform_turn`：戏剧目标、话语行为、0～3 级强度，以及可选的教学目标、具体概念和期待回应。它不选择动画片段、道具坐标或关节参数。普通 OpenAI-compatible LLM 使用同一份 JSON 语义契约，因此 Audio-to-Audio 与 LLM + ASR + TTS 不会形成两套角色控制逻辑。

当调用包含 `concept: "apple"` 时，`embodiedInteraction.ts` 会把一个意图展开成可中断的完整场景：察觉、拿出苹果、共同注视、命名、递近、邀请跟读、等待、表扬或提示、自然收势。现在对象帧拥有能力和生命周期：香蕉可拿取，圣诞帽可从手中移动到头部，蛋糕可靠近嘴部并按咬食进度消失，礼物可进入打开状态。对象锚点覆盖左右手、双手、头部、嘴部和舞台；未知对象默认使用安全 Emoji，并只允许展示、递近和放下。后续替换为精细 SVG 只需更新对象目录，不改页面流程。

实时输出音频也会转成 `VoiceFeatures`，与语义意图在统一时钟上共同驱动嘴型、面部和身体。当前音频适配器仍使用能量、亮度与重音特征；接入 Audio2Face 后可替换为更细的 viseme/blendshape 数据。

## 语音与模型 API

页面内的“语音与模型 API”面板提供两条可切换管线：

- **Audio-to-Audio**：当前接入 Gemini Live。可以填写模型、声音和 API Key；Key 留空时会请求 `/api/gemini-token`。
- **LLM + ASR + TTS**：填写 OpenAI-compatible Chat Completions 完整地址、模型和 API Key。输入使用浏览器 Web Speech ASR，输出使用 Azure Speech 情绪语音；viseme 时间轴和情绪韵律会与表情、眼神、嘴型及身体动作共享表演时钟。

## 角色语音与台词

30 种导演状态各有五句短台词，共 150 句，其中每个状态至少两句以英语为主。自动表演会记住最近四句台词，优先从同一戏剧目标的候选池中选择没有刚说过的句子；重复点击状态也会向后轮换。选中状态后仍可直接点任意一句。台词与动作使用相同的戏剧目标，因此不会出现“身体在哭，声音却在庆祝”的错配。

默认角色声线是 Azure `zh-CN-YunxiNeural` 的 `Boy` 角色。同一个演员按状态切换 `cheerful`、`sad`、`embarrassed`、`fearful`、`narration-relaxed`、`serious` 等 SSML 风格，并进一步控制风格强度、速度、音高和音量。这样角色身份保持稳定，表演状态却能明显变化。

Azure adapter 先合成带时间戳 viseme 的 WAV，再由同一 Web Audio 时钟播放；每个 viseme 在对应 audio offset 到达时写入 `VoiceFeatures` 的 `jawOpen`、`mouthWide` 和 `mouthPucker`。没有 Azure Key 时不会退回僵硬的系统 TTS，而是在页面提示填写 Speech Key 和 Region。

角色语音 seam 保留了本地开源 adapter 的位置。Kokoro 82M 适合未来的纯浏览器 WebGPU/WASM 路线；MeloTTS 适合本地 Python/CPU 服务和中英混说。当前先采用 Azure，是因为它同时提供稳定的男孩角色、情绪 SSML 和官方 viseme 时间戳。

表单里的 Key 只存在 React 页面内存，不写入 localStorage。它仍然会由浏览器直接发送给所填服务，因此只适合本地实验；公开部署时应把 Chat Completions 地址换成自己的服务端代理。浏览器 ASR 推荐使用 Chrome 或 Edge，并需要麦克风权限。

开发环境也可以临时设置 `VITE_GEMINI_API_KEY`（只适合个人实验）。部署到 Netlify 时，建议设置服务端变量 `GEMINI_API_KEY`，页面会请求 `/api/gemini-token` 获取一次性短期令牌，浏览器不会收到长期 API Key。

需要在浏览器中授权麦克风；“开启眼神交流”会启用本地 Google MediaPipe Face/Hand Landmarker，并用双眼中点定位孩子。鼠标不再控制雪宝的眼球。摄像头只提供孩子相对方向，`socialGaze.ts` 根据倾听、说话、思考和空闲状态安排自然的看向、移开与看回；摄像头画面不发送给模型，只有低频语义事件进入实时会话。

## 文件职责

- `rig.ts`：完整连续 Rig、输入样本与参数范围。
- `performanceScore.ts`：把一段表演采样为察觉、判断、蓄力、行动、反馈和收势，并输出连续表演曲线。
- `performanceModel.ts`：统一时钟、输入融合、意图衰减、约束、平滑和可替换策略适配器。
- `socialGaze.ts`：社交注视导演；将脸部目标与表演状态变成连续的眼神接触、视线回避、头部跟随和换视线眨眼。
- `performanceImproviser.ts`：五层演员深模块；包含稳定人格、戏剧目标、演员状态、六段动作编排及连续 Rig 输出。
- `olafTheater.ts`：儿童单口剧场深模块；以“采样当前表演 + 确认台词完成”的接口隐藏剧目随机、七拍喜剧结构、短台词、动作匹配和完成驱动的自然转场。
- `embodiedInteraction.ts`：具身教学导演；把语义教学意图展开为道具、共同注视、短台词、等待回应和反馈收势。
- `actionDirector.ts`：将 Gemini 工具和本地感知翻译成连续 `PerformanceInput`。
- `geminiLive.ts`：Gemini Live WebSocket、紧凑 `perform_turn` 语义工具、实时 PCM 音频。
- `characterSpeech.ts`：150 句中英角色台词、近期去重选句、状态到声音表演的映射、SSML 和 viseme 嘴型映射。
- `azureSpeechOutput.ts`：Azure 情绪语音合成、音频播放和带时间戳的嘴型驱动。
- `textVoiceSession.ts`：OpenAI-compatible LLM 会话与可替换角色语音 adapter。
- `browserAsr.ts`：浏览器 Web Speech ASR 输入适配器。
- `voicePipeline.ts`：两条语音管线的配置与会话工厂。
- `audioAnalyzer.ts`：麦克风采集、语音特征和 PCM 播放队列。
- `localPerception.ts`：本地 Face/Hand Landmarker。
- `OlafLiveCharacter.tsx`：按手部、双手、头部、嘴部和舞台锚点渲染连续 Rig 与场景物体；当前默认使用 Emoji，精细 SVG 可替换对象目录。
